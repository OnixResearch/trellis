- `src/mesi.rs:invalidate_others_spec` closed cleanly with small recursive lemmas for length preservation, unchanged indices below `from`, writer preservation, and target-index invalidation.
- Keep MESI exec paths iterative. A recursive exec helper over cache entries verifies, but it is a runtime regression because recursion depth grows with `caches.len()` and can blow the Rust stack.
- `src/page.rs:radix_index_bounded` closed with a tiny bit-vector helper over `(value >> offset) & ((1 << width) - 1)` plus an explicit arithmetic proof that the computed offset is `< 64`.
- `src/topo_sort.rs:is_topo_order` no longer needs an `assume(...)` oracle. The stable proof shape was: keep the runtime checker iterative, add recursive bridge lemmas from pointwise/pairwise facts to `all_in_range_spec` / `all_distinct_spec` / `edges_forward_spec`, and make the edge-position scans record the first matching index by guarding updates with `pu == n` / `pv == n`.
- `src/reachability.rs` closed once `reachable_spec` stopped pretending the fixed budget `n` was the essence of the property. The clean model is existential reachability (`exists fuel. reachable_fuel(...)`), after which edge extension is the true lemma: `reachable_fuel(src, u, fuel)` plus `(u, dst)` yields `reachable_fuel(src, dst, fuel + 1)` with no `assume(...)` corner case.
- `src/nix_closure.rs` closed only after an API redesign. The old `&dyn Fn` interface was not meaningfully verifiable, so the closeable gap disappeared by switching the runtime API to a finite operator table `Vec<(u64, Vec<ClosureItem>)>`, replacing the placeholder spec with a real closure predicate over reachable keys and closure-closed results, and keeping the runtime executor as an ordinary Rust wrapper outside `verus!`.
- Verus here does not model slice `.to_vec()` in exec code. For verified clone/copy helpers over `&[u64]`, `&[BeamMessage]`, or similar slices, build the result with an explicit loop and an invariant over `subrange(0, i)` instead of calling `.to_vec()`.
- For structs containing `Vec`, Verus often fails to prove whole-struct equality after cloning the vector field. Prefer fieldwise postconditions (`pid/state/...` plus `heap@ =~= old.heap@`) over `result == spec_struct` unless the struct is entirely copy-like.
- For small BEAM-style value models without a global allocator, phrase heap-isolation requirements in terms of distinct pids rather than globally fresh process creation. `heap_id = pid` is a sound model only when the requirement text says distinct pids imply distinct heap identities.
- Done review checks cross-module `properties.*` rules against the prose in `docs/requirements.md`, not just the rule IDs. If the requirement mentions unlink state, exact-once delivery, or cleanup roundtrips, the property spec must carry those same state variables and quantify that behavior explicitly.
